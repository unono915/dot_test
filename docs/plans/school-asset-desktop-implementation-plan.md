# 학교 정보자산 관리 프로그램 구현 계획

작성일: 2026-10-05

[승인된 제품 명세](../specs/school-asset-desktop-review.md)를 바탕으로 전체 프로그램의 구현 순서와 검증 기준을 정리했다. 이 문서는 개발 계획이며, 기능 구현이나 시험 통과를 보고하는 문서는 아니다.

## 완성할 프로그램

정보부 관리자 한 사람이 Windows PC에서 인터넷 없이 자산·교직원·장소·IP를 관리한다. 엑셀 최초 이관부터 배정·반납·이동·대여·수리·퇴역·폐기, 실사와 PC 교체, 인계 자료 출력, 새 PC 복원까지 한 흐름으로 제공한다. 모든 개별 자산 ID와 변경 이력을 보존한다.

교내망 스캔, 자동 수집, 장비 설정 변경, 교사 포털, 다중 사용자, 클라우드 동기화와 원격 분석은 포함하지 않는다. 실제 학교 자료 대신 합성 데이터로 개발·검증한다. 개발 완료가 외부 배포·게시를 의미하지 않는다.

## 설계 선택

| 영역 | 선택 | 이유와 확인할 위험 |
|---|---|---|
| 데스크톱 | Electron, Windows 11 x64 우선 | 일반 OS 계정 설치와 오프라인 업무를 제공한다. Linux 실행은 Windows 검증을 대신하지 않는다. |
| 화면 | React·TypeScript, 로컬에 묶은 UI 자원 | 이관 검토·실사·복원 같은 복잡한 화면 상태를 일관되게 관리한다. 외부 글꼴·웹 서비스에 의존하지 않는다. |
| 업무 데이터 | main 프로세스 소유 SQLite | 업무 변경·이력·명령 결과를 한 트랜잭션으로 저장한다. 긴 일괄 작업의 화면 응답성을 별도로 측정한다. |
| 첨부 | 해시 기반 불변 파일 | 큰 파일을 DB와 분리하면서 과거 이력이 참조하는 첨부를 보존한다. DB와 함께 백업해야 한다. |
| 파일 이관 | 제한된 XLSX 파서와 검토 절차 | 엑셀을 신뢰하지 않고 크기·행·셀·수식·관계·중복을 검증한다. 애매한 매칭은 자동 병합하지 않는다. |
| 복원 | 비활성 데이터 세대 준비 후 전환 | 기존 자료를 덮어쓰지 않는다. 전환 단계의 강제 종료와 재시작까지 검증한다. |

계획의 직접 의존성 선택은 Electron 44.5.1, React 19.3.0, TypeScript 6.0.3, better-sqlite3 13.0.3, ExcelJS 4.4.0이다. Vite·Vitest·Playwright와 스트리밍 ZIP 도구를 사용한다. 정확 버전·공식 출처·lockfile을 확인해 설치했으며 Node와 Electron Node 모드의 SQLite 도구 검사, 일반 Linux 데스크톱의 최소 창·렌더러 진단을 통과했다. 제품 GUI·배포 앱·Windows 호환성 검증은 아직 완료하지 않았다. 최신 결과와 한계는 [README](../../README.md)를 따른다.

대안도 비교했다. 첨부를 SQLite BLOB으로 통합하면 백업은 단순하지만 큰 DB의 복사·입출력 부담이 커진다. 별도 데이터 프로세스는 긴 작업 격리에 유리하지만 프로세스 간 장애 복구가 추가된다. 우선 단일 main 소유 DB와 불변 첨부를 구현하고, 응답성 목표를 만족하지 못하면 범위·원자성을 유지하는 방식으로 구조를 재검토한다.

## 모든 단계에 적용할 규칙

- 변경 전후 값, 이유, 시각, 행위자와 성공한 명령 결과를 함께 저장한다. 감사 기록 실패도 전체 작업 실패다.
- 같은 명령의 반복 실행은 한 번만 반영한다. 오래된 편집 내용은 현재 값을 덮어쓰지 않는다.
- 복원·롤백 때는 새 세대 식별자를 발급한다. 과거와 revision 숫자가 같아도 이전 세대의 폼·미리보기·파일 접근 승인은 재사용할 수 없다.
- 퇴직·전원 꺼짐·실사 미발견으로 IP를 자동 해제하지 않는다. 해제 대기도 계속 점유한다.
- 관측 자료는 배정 대장과 분리한다. 수동 확인이 실제 LAN 무충돌을 보장한다고 표현하지 않는다.
- 실사 시작 당시 기준과 현재 장부를 구분한다. 실사 결과가 최근 이동을 덮어쓰지 않는다.
- 큰 이관과 일괄 변경은 적용 대상으로 확인한 묶음 전체가 성공하거나 모두 롤백한다.
- 파일 오류·취소·디스크 부족·재시작 이후에도 성공/실패를 사실대로 보여준다.
- 실제 개인정보·네트워크 접근, 유료 서비스, 보안 권한 확대는 자동으로 추가하지 않는다.

## 개발 순서와 단계별 완료 조건

각 작업은 실패해야 하는 시험을 먼저 작성하고, 실제 실패를 확인한 뒤 최소 구현과 성공 시험을 거친다. 한 단계의 기능이 다른 단계의 미완료 기능 때문에 검증 불가능해지지 않도록 공통 계약을 먼저 고정한다. 작업 결과는 로컬 변경과 시험 증거로 남긴다.

### 1. 안전한 앱과 데이터 기반

Electron 창, 한국어 기본 화면, 제한된 IPC, 로컬 자원 제공, 데이터 디렉터리와 단일 인스턴스 처리를 만든다. 실제 Electron의 SQLite 로딩·버전·트랜잭션·백업 기능을 확인한다. 명령 ID, 기대 버전, 세대 식별자, 감사 기록과 데이터 revision을 공통 저장 경계로 구현한다.

**완료 조건:** 중복 명령은 한 번만 반영되고 오래된 버전·다른 세대의 요청은 거부된다. 불정상 IPC 출처나 임의 파일·SQL·셸 요청은 실행되지 않는다. 두 번째 앱이 같은 DB를 쓰지 못한다.

### 2. 자산과 사람·장소의 전체 업무

개별 장비 등록·검색·수정, 교직원·계층형 장소, 기본 배정과 반납, 일괄 이동, 대여·연체·반납, 수리·완료, 분실 확인·회수, 퇴역·폐기를 구현한다. 공식 물품번호·serial과 내부 ID를 구분하고 과거 기록의 정정은 새 사건으로 남긴다.

**완료 조건:** 모니터는 인터페이스 없이 등록된다. 퇴직해도 보유 장비가 사라지지 않는다. 일괄 이동 실패 시 일부만 이동하지 않는다. 폐기에 필요한 정리 조건과 폐기 오기 정정이 명시대로 작동한다.

### 3. 인터페이스·실제망·IP·관측

전체 IPv4와 비중첩 CIDR, 망 별칭, static/DHCP/제외 범위, 인터페이스를 구현한다. 예약·활성·해제 대기·최종 해제·이전 명령을 같은 도메인 규칙으로 보호한다. 관측 회차별 증거와 배정 revision을 비교해 일치·불일치·의심·불명을 구분한다.

**완료 조건:** 같은 실제망/IP의 중복 점유는 DB에서도 거부된다. 별칭·중첩망·엑셀 경로로 우회할 수 없다. 근거 없는 이전은 보류되며, 정상 교체 전후의 다른 관측 회차를 충돌로 잘못 합치지 않는다.

### 4. 실사와 미해결 업무

실사 시작 시 대상과 당시 장소·담당·버전을 고정한다. 일치·불일치·미발견·미확인 결과와 현재 대장의 변경을 함께 표시한다. 대여 연체, 퇴직자 보유, 망 확인 필요, 해제 대기 등에서 원인 레코드로 이동할 수 있게 한다.

**완료 조건:** 기준 100개는 실사 중 새 장비를 추가해도 100개다. 기준 장소 A에서 B로 이동한 장비를 B에서 확인하면 기준 대비 불일치·현재 대장 일치를 함께 보인다. 실물 확인 시각과 IP 관측 시각을 섞지 않는다.

### 5. 엑셀 이관·출력과 첨부

시트·열 매핑, 형식·관계 검증, 신규/변경/동일/충돌 검토, 적용할 행의 확정, 전체 적용과 결과 보고를 만든다. 안정키가 없는 초기 자료에는 정규화본을 제공한다. 자산대장·인계·실사·미해결 보고서와 안전한 첨부 저장을 제공한다.

**완료 조건:** 같은 원본을 다시 가져와도 장비가 늘어나거나 최근 수동 수정이 되돌아가지 않는다. 미리보기 이후 자료가 바뀌면 재검토한다. 선행 0을 보존하고 수식·실행 가능한 내용·과도한 압축 파일을 거절한다. 출력은 하나의 기준 시점으로 일관된다.

### 6. 일관 백업과 복원·롤백

쓰기를 정리한 뒤 DB·역사 첨부·필수 설정·유지보수 기록을 한 기준으로 백업한다. 복원 파일은 비활성 세대에서 형식·길이·해시·DB·도메인 규칙을 검사한다. 활성 데이터 전환, 이전 세대 보존, 시작 시 복구, 수동 롤백과 보존 세대 정리를 구현한다.

**완료 조건:** 손상 파일은 현재 자료를 바꾸지 않는다. 전환 중 앱이 종료돼도 서로 다른 세대의 DB와 첨부를 혼합하지 않는다. 새 PC에서는 경로를 재구성하고 기존 이력에 정확히 한 개의 복원 사건을 추가한다.

### 7. 한국어 화면·성능·오프라인 설치·인계

전체 업무를 실제 앱에서 연결하고 키보드·포커스·긴 한글·배율·오류·취소 흐름을 다듬는다. 합성 규모 시험과 장시간 파일 작업을 측정한다. 가능한 설치 파일을 만들고 라이선스 고지와 오프라인 도움말·인계 예제를 포함한다.

**완료 조건:** 처음 이관한 자산을 일상 업무·실사·IP 교체에 사용한 뒤 인계 파일과 백업을 만들고 새 Windows PC에서 복원하는 통합 사례가 통과한다. Windows 증거가 없는 항목은 미검증으로 남기며 완료로 표시하지 않는다.

| AC-45 | 2–7 | 이관부터 업무·인계·새 PC 복원까지 통합 사례 |

## 우선 검토할 실패 사례 다섯 가지

1. **저장 응답을 잃은 뒤 복원으로 같은 revision 숫자가 다시 등장한다.** 기존 성공 명령은 중복 적용하지 않고, 이전 세대의 폼·명령·파일 토큰은 거절해야 한다.
2. **파일을 선택한 뒤 원본이 바뀌거나 Windows 경로 표현이 겹친다.** 검증한 내부 복사만 사용하고 대소문자·예약 이름·링크·경로 충돌을 검사해야 한다.
3. **수동으로 수정한 뒤 과거 엑셀을 다시 가져온다.** 동일한 원본의 재실행이 최근 수정을 되돌리거나 장비를 중복 생성하면 안 된다.
4. **실사 도중 장비가 이동하거나 관측 시각이 역전된다.** 실사 기준을 유지하고 미발견·IP 관측으로 최근 실물 확인을 덮어쓰면 안 된다.
5. **저장 공간이 부족하거나 해시는 정상이지만 업무 관계가 잘못된 백업을 복원한다.** 현재 자료를 보존하고 도메인 규칙까지 검증해야 한다.

각 항목은 해당 기능의 자동 시험과 실제 앱 흐름 시험에 함께 배정한다. 같은 이름·물품번호·serial의 애매한 자동 병합과 한글 IME 입력 중 Enter·반복 저장·포커스도 별도 필수 시험으로 유지한다.

## 주요 위험과 대응

| 위험 | 대응과 증거 |
|---|---|
| 실제 내장 SQLite의 버전·무결성 문제 | 실제 엔진 버전/소스 ID와 패치 여부 기록, FK·무결성·도메인 검사, 재시작·백업 시험 |
| main의 큰 동기 작업으로 화면 정지 | 파일 파싱/해시 작업 분리, 명령별 시간 측정, 진행/취소 시점 검증. 원자성을 포기해 성능을 맞추지 않음 |
| 엑셀·압축 파일의 비정상 크기/수식/경로 | 라이브러리 전후 실제 바이트·행·셀 제한, 안전한 비활성 위치 처리, 악성 합성 자료로 거부 시험 |
| 복원 중 종료와 여러 파일의 세대 혼합 | 완성된 세대만 전환, 독립된 전환 기록, 이전 세대 보존, 단계별 강제 종료 시험 |
| 수동 확인 근거의 부정확성 | 확인 없는 IP 해제·이전은 차단하고 실제 무충돌 보장은 하지 않음 |
| Windows 빌드·네이티브 모듈 문제 | 대상 플랫폼 파일 포함과 실제 main 로딩 검사. 크로스 빌드 성공과 Windows 실행 성공을 분리 |
| 자동화 환경과 배포 환경의 차이 | 테스트용 설정 차이를 기록하고 최종 배포 빌드를 별도 확인. 보안을 조용히 낮추지 않음 |

사전 실패 가정은 세 가지다. 첫째, 응답을 잃은 명령을 다시 적용해 자산/IP가 중복된다. 둘째, 엑셀 이관이나 복원이 최근 수정·관계를 훼손한다. 셋째, 개발 환경에서만 잘 동작하고 실제 Windows 설치·복원이 실패한다. 각각 멱등 명령과 버전 검사, 전체 원자성·세대 검증, 실제 Windows 별도 시험으로 예방한다.

## 검증 범위와 완료 판정

| 검증 층 | 대상 |
|---|---|
| 정적 검사 | 타입·lint·빌드, 허용되지 않은 통신·IPC 통로 검토 |
| 단위 시험 | IP 범위·상태 전이·키 매칭·수량·관측 판정·입력 제한 |
| DB/파일 통합 | 트랜잭션·동시 요청·이관·첨부·백업·복원·실패 주입 |
| 화면/앱 시험 | 실제 Electron의 업무 흐름·대화상자·취소·반복 클릭·오프라인·스크린샷 |
| 규모 시험 | 자산 10,000, 사람 2,000, 장소 300, 인터페이스 30,000, 망 64, 주소 100,000, 관측 100,000, 감사 500,000, 첨부 10GB |
| Windows 시험 | 일반 사용자 설치·재설치·제거, 네이티브 로딩, 한글/배율, 오프라인, 강제 종료/복구, 빈 새 PC 복원 |

기준 PC는 SSD·RAM 8GB·논리 CPU 4개다. 검색 첫 페이지 p95 1초, 단건 쓰기 p95 500ms, 시작 5초, 50,000행 미리보기 60초·적용 120초, 10GB 백업/복원 각각 15분을 목표로 측정한다. 각 실행 기록에는 앱 빌드·환경·데이터 규모·명령·결과·소요 시간·증거 파일을 남긴다.

파일 상한은 명세와 동일하게 XLSX 25MB, 해제 250MB, 시트 20개, 데이터행 50,000개, 비어 있지 않은 셀 1,000,000개, 매핑 열 100개다. 첨부는 파일당 25MB·누적 10GB, 백업은 번들/해제 각각 15GB·항목 100,000개다. 상한 초과를 조용히 잘라서 성공으로 처리하지 않는다.

각 수용 기준은 통과·실패·미실행으로 구분한다. 필수 기준과 통합 사례가 통과하고 인계 문서까지 갖추어야 완성이다. 현재 제품 시험 결과는 없으며, 실제 Windows 환경이 없는 동안 Windows 항목은 미실행으로 남긴다. Linux 시험·패키징을 그 대신으로 인정하지 않는다.
